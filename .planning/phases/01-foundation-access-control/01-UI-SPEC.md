# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Mode note:** This UI-SPEC was produced in `--auto` (non-interactive) mode. No CONTEXT.md exists for this phase, and the repository is greenfield (no `package.json`, no `components.json`, no `src/` — confirmed by codebase scan). Every decision below that would normally be asked of the user was instead made by the researcher using project constraints from CLAUDE.md (non-technical legal audience, shadcn/ui + Tailwind v4 locked stack) and RESEARCH.md's architecture. Rationale is recorded per decision so the planner/executor/checker can trace *why*, and so a human can override any of these at review time.

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (locked per CLAUDE.md stack) — **not yet initialized**. This is a greenfield repo; `apps/web` scaffolding and `npx shadcn init` are themselves Phase 1 execution tasks (Wave 0), not something this research session can run against a real project. |
| Preset | `style=new-york`, `baseColor=neutral`, `cssVariables=true`, Tailwind v4. Recommended non-interactively (see rationale below) so the executor can run `npx shadcn init --preset new-york-neutral` (or the equivalent CLI flags) during scaffolding without a blocking human round-trip. |
| Component library | Radix UI primitives (via shadcn) |
| Icon library | `lucide-react` — shadcn's default pairing, MIT-licensed, tree-shakeable, already implied by any standard shadcn init |
| Font | Inter, with fallback stack `Inter, ui-sans-serif, system-ui, sans-serif` |

**Decision rationale (auto-mode, no CONTEXT.md):**
- **New York style over Default:** New York reads denser and more formal (tighter radii, more structured card/table chrome) than shadcn's "Default" style, which skews toward a lighter startup/marketing feel. A legal-department admin tool (workspace/role management, audit-adjacent data) benefits from the more formal, information-dense register. Reversible at low cost — a style choice, not a schema decision.
- **Neutral base color over Slate/Zinc/Blue:** Neutral avoids a cool blue-gray tech tint (Slate) and reads as the most conservative, brand-agnostic option — appropriate for an open-source tool that legal departments across many organizations will white-label/reskin. The single accent color (below) carries all brand personality instead of the base palette.
- **Inter as the font:** Inter is designed for UI/data-dense legibility at small sizes (form labels, table cells) and is the de facto standard pairing for shadcn dashboards (Linear, Vercel, Notion-adjacent B2B SaaS) — a safe, highly-legible default for a forms-and-tables-heavy admin surface used by non-technical staff.
- **shadcn not yet initialized:** The shadcn gate normally asks the user to paste a preset string from `ui.shadcn.com/create`. In `--auto` mode with a genuinely empty repo, there is no `components.json` to detect and no interactive channel to collect that string. The preset above is this session's non-interactive substitute — the Phase 1 plan's Wave 0 scaffolding task should apply it (or a human can override before scaffolding runs).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge internal padding |
| sm | 8px | Compact element spacing (form label-to-input gap, table cell vertical padding) |
| md | 16px | Default element spacing (form field stack gap, card internal padding) |
| lg | 24px | Section padding (card padding on desktop, dialog padding) |
| xl | 32px | Layout gaps (space between page header and content, auth-form top margin) |
| 2xl | 48px | Major section breaks (space above/below the auth form on the login/register page) |
| 3xl | 64px | Page-level spacing (top padding on the auth screen, centering the form vertically on tall viewports) |

Exceptions: none. This is a desktop-first admin dashboard (lawyers on laptops per CLAUDE.md's audience framing); no mobile-specific 44px touch-target exception is declared for Phase 1. Standard shadcn control heights (40px inputs/buttons) already exceed typical desktop click-target minimums.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- **Body (16/400/1.5):** Form field values, table cell content, member list rows, empty-state body copy.
- **Label (14/400/1.5):** Form field labels, table column headers, helper/secondary text, role badges.
- **Heading (20/600/1.2):** Section headers within a page — "Workspaces", "Members", "Create workspace" dialog title.
- **Display (28/600/1.2):** Page-level titles — "Sign in to Skillshare", "Create your account".

Exactly two weights (400, 600) and four sizes, per contract rules. No third weight (e.g. medium/500) is introduced anywhere in Phase 1 — role badges and table headers use Label size at 400 weight, distinguished by color/background rather than a third weight.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white — shadcn `background` token, light mode) | Page background, form panels, dialog/modal background, table body background |
| Secondary (30%) | `#F4F4F5` (zinc-100 — shadcn `muted`/`card` token) | Card surfaces, table header row background, sidebar/workspace-nav background, alternating table row shade |
| Accent (10%) | `#4F46E5` (indigo-600) | See explicit reserved-for list below — never used as a general interactive-element color |
| Destructive | `#DC2626` (red-600) | Destructive actions and error surfaces only — see explicit reserved-for list below |

**Accent reserved for (explicit list, never "all interactive elements"):**
- Primary CTA buttons: "Create account", "Log in", "Create workspace", "Grant access"
- The active/selected item indicator in the workspace nav (left border or background tint + text color)
- Focus ring outline on any focusable control (accessibility, not decorative)
- The "Admin" role badge fill (Editor and Consumer badges use the neutral/secondary palette, not accent — Admin is the only role visually flagged, since it is the one that carries elevated risk)

**Destructive reserved for:**
- "Remove member" button and its confirmation dialog's confirm action
- Inline field-level validation error text and error banners (e.g. invalid login, duplicate email, workspace-name conflict)
- Any "session expired / permission denied" alert

Light mode only is specified for Phase 1; dark mode is not a stated requirement and is left to shadcn's default CSS-variable theming (free if `cssVariables=true` is honored at init, per the Design System preset above) rather than hand-specified here.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Register | "Create account" |
| Primary CTA — Login | "Log in" |
| Primary CTA — Create workspace (Admin) | "Create workspace" |
| Primary CTA — Grant role (Admin) | "Grant access" |
| Empty state — no authorized workspaces (any user, including a brand-new registrant) | Heading: "No workspaces yet." Body: "You haven't been granted access to any workspace. Ask an admin to add you." (No CTA — self-service workspace creation is Admin-only.) |
| Empty state — org has zero workspaces (Admin) | Heading: "Create your first workspace." Body: "Workspaces organize skills by practice area, like Employment Law or M&A. Create one to get started." CTA: "Create workspace" |
| Empty state — workspace has no members beyond its creator (Admin) | Heading: "No members yet." Body: "Grant a role to add the first person to this workspace." CTA: "Grant access" |
| Error — invalid login | "That email or password is incorrect. Check your details and try again." (Deliberately does not disclose which field is wrong — standard login-enumeration mitigation.) |
| Error — duplicate registration | "An account with this email already exists. Log in instead." (Accepted enumeration tradeoff: this is a single-organization self-hosted tool where an admin already controls who is invited/granted workspace access; a clear duplicate-account message is more useful to a non-technical user than enumeration-hardened ambiguity. Flag for the planner to confirm if the org later goes multi-tenant/public-signup.) |
| Error — workspace name conflict (Admin) | "A workspace named '{name}' already exists. Choose a different name." |
| Error — permission denied (403, cross-workspace access attempt) | "You don't have access to this workspace. Contact your admin if you think this is a mistake." |
| Error — generic / network failure | "Something went wrong. Please try again — if this keeps happening, contact your admin." (Every error surface with a Retry affordance uses this exact copy unless a more specific message above applies.) |
| Destructive — remove member (Admin; anticipated, see note) | Action label: "Remove member". Confirmation dialog: "Remove {name} from {workspace}? They'll lose access to every skill in this workspace immediately." Buttons: "Remove" (destructive style) / "Cancel". |

**Note on "Remove member":** Phase 1's stated success criteria only require granting a role (ORG-02); revoking/removing a member is not explicitly listed. This confirmation pattern is provided proactively because role management UIs conventionally need a revoke path and "grant a role" is commonly read to include "manage" — but this is flagged, not assumed as in-scope. Confirm with the planner whether remove/revoke is built in Phase 1 or deferred.

## UI Considerations

Applicable state considerations resolved: 12 covered, 2 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | workspace-list (list-collection) | ✅ covered | Admin with zero org workspaces sees the "Create your first workspace" empty state with its CTA; a non-admin/user with zero authorized workspaces sees the "No workspaces yet" empty state with no CTA (self-service creation is Admin-only) — see Copywriting Contract rows. |
| empty | member-role-table (list-collection) | ✅ covered | A workspace with no granted members beyond its creator shows the "No members yet" empty state with the "Grant access" CTA — see Copywriting Contract row. |
| loading | register-form, login-form (form) | ✅ covered | Submit button shows an inline spinner and disables itself for the duration of the request; no full-page loading state is needed for a single-field-set form. |
| loading | workspace-list (list-collection) | 🧪 backstop | Workspace list renders skeleton rows while the initial fetch is in flight. Held-out loading-state test at implementation time; not asserted by copy alone. |
| error | login-form (form) | ✅ covered | Invalid-credentials failure renders the "invalid login" copy inline above the form fields — see Copywriting Contract row. |
| error | workspace-list (list-collection) | ✅ covered | Fetch failure renders the generic error banner with a Retry action, using the "generic / network failure" copy row. |
| error | member-role-table (list-collection) | ✅ covered | A failed grant (duplicate grant, unresolvable user) surfaces an inline error under the grant-role form using the same generic/specific error copy pattern as workspace-name conflict. |
| populated | workspace-list (list-collection) | ✅ covered | Normal state renders one row/card per authorized workspace, showing name + the caller's role badge; the "Admin" badge uses the accent color, "Editor"/"Consumer" use the neutral palette. |
| populated | member-role-table (list-collection) | ✅ covered | Normal state renders one row per member with name/email, role badge, and (Admin viewer only) a "Remove member" action. |
| zero-one-many | workspace-list (list-collection) | ✅ covered | Copy uses singular/plural workspace count ("1 workspace" vs "3 workspaces") in any summary header; the list layout itself is a single-column stack, unaffected by count. |
| zero-one-many | member-role-table (list-collection) | ✅ covered | Table layout is stable at 1 vs many rows; no special-casing beyond the empty state above. |
| overflow | workspace-list (list-collection) | ✅ covered | Workspace names longer than the row width truncate with an ellipsis; the full name is available via a title attribute/tooltip on hover. |
| overflow | member-role-table (list-collection) | ✅ covered | Member email/display name truncates with ellipsis; the role badge itself never truncates (fixed 3-word vocabulary: Admin/Editor/Consumer). |
| overflow | app-nav (nav) | 🧪 backstop | The sidebar workspace-nav list becomes internally scrollable past roughly 10 entries rather than pushing page content down. Held-out overflow-state test at implementation time. |
| long-text | register-form, login-form (form) | ✅ covered | The email input scrolls horizontally within a fixed-width field rather than resizing the form or wrapping. |
| partial | create-workspace-form (form) | ⚠ unresolved | No autosave/draft-recovery behavior is specified for a partially-filled create-workspace form if the browser closes mid-entry. Treated as out of scope for Phase 1 (single-step form, no autosave) — planner should record this as an explicit assumption rather than silently building autosave or silently dropping the concern. |
