<objective>
Deliver the role-grant + cross-workspace isolation slice (ORG-02, and the enforcement half of
ORG-03): an Admin grants per-workspace roles, and a role in one workspace confers nothing in
another. This introduces the `WorkspaceRoleGuard` — the single structural enforcement point that
makes "unauthorized requests never receive content" true across every future channel.

Purpose: Complete the permission backbone. The guard + per-workspace membership check is the
security-critical primitive that Phases 4/5 (REST, CLI, MCP) reuse verbatim.
Output: Admin-only per-workspace role grant, deny-by-default cross-workspace isolation with
non-leaking 403s, and the member-management UI, verified end to end including a Playwright
visibility test.
</objective>

|----------|-------------|
| client → /api/workspaces/:workspaceId/* | Workspace ID is attacker-controlled; membership must be verified per request |
| client → grant-role endpoint | Only a per-workspace Admin may grant; role is validated server-side |

## STRIDE Threat Register (ASVS L1, block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | workspace ID tampering (IDOR) | high | mitigate | WorkspaceRoleGuard checks the caller's actual Membership row for the requested `:workspaceId` on every request; never trusts a workspace ID without a membership lookup (RESEARCH Security Domain) |
| T-05-02 | Elevation of Privilege | role self-assignment / cross-workspace grant | high | mitigate | Grant is a separate Admin-only endpoint validated against the role enum; per-workspace Admin authority verified (an Admin of A cannot grant in B) |
| T-05-03 | Information Disclosure | cross-workspace 403 body | high | mitigate | Denial responses are generic permission-denied shapes that do not confirm existence or disclose the workspace name (ORG-03 non-leak prohibition) |
| T-05-04 | Tampering | concurrent grant/revoke vs list | low | mitigate | `@@unique([userId, workspaceId])` upsert; list reads reflect a consistent membership snapshot (edge #9 backstop) |
</threat_model>
